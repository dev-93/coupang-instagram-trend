# 재사용 가능한 Telegram 메시지 포맷

이 가이드는 모바일에서 빠르게 훑고, 필요한 근거만 펼쳐 읽는 메시지 구조를 다른 프로젝트에 옮길 때 사용한다. 프로젝트마다 섹션 이름과 내용을 바꾸되, 순서와 시각적 위계를 유지한다.

## 권장 구조

1. 프로젝트 표시와 주제를 한 줄 제목으로 둔다.
2. 대상이나 상황을 제목 바로 아래 한 줄로 요약한다.
3. 핵심 판단이나 가설을 먼저 보여준다.
4. 실행 방법을 짧은 번호 목록으로 적는다.
5. 연결 대상, 다음 행동, 확인할 지표를 구역별로 분리한다.
6. 긴 근거·세부 메모는 펼쳐 읽는 인용 블록에 모은다.
7. 미확인 사항, 결과의 한계, 원본 기록 링크와 시각으로 끝낸다.

## 복사해 쓸 수 있는 레이아웃

```html
[프로젝트] <b>{주제} · {알림 종류}</b>
<i>대상 또는 상황: {한 줄 설명}</i>

💡 <b>이번에 볼 가설</b>
{검증 가능한 가설 한 문장}

🎬 <b>실행 구성</b>
<b>첫 부분</b> “{시작 문구}”
1. {첫 장면 또는 단계}
2. {둘째 장면 또는 단계}
3. {셋째 장면 또는 단계}

🛒 <b>연결 또는 다음 행동</b>
{무엇을 어떻게 연결하는지}
<b>이유</b> {사용자가 다음 행동을 할 수 있는 이유}

💬 <b>마무리 문구</b>
{사용자에게 보여줄 문장}

✅ <b>확인할 점</b>
• {게시·실행 전 확인 1}
• {게시·실행 전 확인 2}

📊 <b>확인할 반응</b>
{무슨 지표를 언제 볼지}

<blockquote expandable><b>🔎 근거·검토 메모 — 펼쳐보기</b>
<b>문제</b> {관찰한 구체적 문제}
<b>현재 대안</b> {현재 해결 방법}
<a href="{sourceUrl}">출처 1</a> {근거 요약}
<a href="{sourceUrl}">출처 2</a> {근거 요약}
</blockquote>

<i>{검증 상태나 중요한 한계}</i>
<a href="{recordUrl}">기록 보기</a> · {날짜와 시각}
```

비즈니스 실험이 아니라면 `가설`, `상품 연결`, `구매 이유` 같은 제목을 프로젝트에 맞는 `요약`, `다음 단계`, `영향` 등으로 바꾼다. 짧은 알림에서는 불필요한 구역을 빼고 핵심과 다음 행동만 남긴다.

## Telegram Bot API 적용

- 메시지는 `parse_mode: "HTML"`로 보낸다. 굵은 제목은 `<b>`, 보조 정보는 `<i>`, 출처는 `<a href="…">`, 접을 근거는 `<blockquote expandable>`를 사용한다.
- 외부에서 온 제목·본문·URL을 HTML에 끼워 넣기 전에 `&`, `<`, `>`, `"`를 이스케이프한다. 형식 태그만 코드에서 붙이고, 생성 모델에는 일반 텍스트 데이터만 요청한다.
- 섹션 사이에는 빈 줄을 넣고, 한 구역에는 한 가지 내용만 둔다. 휴대폰에서 먼저 볼 핵심은 펼침 블록 밖에 둔다.
- 링크 미리보기는 끄고, 전송 직전에 길이를 검사한다. 이 프로젝트는 Telegram 제한보다 여유를 둬 3,900자 이내로 보낸다.
- 봇 토큰은 환경 변수나 로컬 비밀 저장소에서만 읽고, URL·오류 로그·예시 코드에 출력하지 않는다.

현재 프로젝트 구현 예시는 [`src/briefing.ts`](../src/briefing.ts)의 `renderBriefing`과 [`src/report/telegram.ts`](../src/report/telegram.ts)에 있다.

공식 참고: [Telegram Bot API — Formatting options](https://core.telegram.org/bots/api#formatting-options), [sendMessage](https://core.telegram.org/bots/api#sendmessage). Telegram은 HTML 형식과 접을 수 있는 인용 블록을 지원하며, `sendMessage` 본문은 형식 적용 후 최대 4,096자로 제한된다.
